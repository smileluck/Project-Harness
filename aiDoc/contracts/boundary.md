# 契约层（boundary）

> 本仓库非 Web/库/传统 CLI，契约双方：生产方 = 本工具包；消费方 = 安装 skill 的 agent 与被初始化的目标仓库。

## 责任边界

| 侧 | 职责 |
|---|---|
| 生产方（本仓库） | skill 路由与 references 的正确性、脚本的安全模型与探测准确性、模板骨架的自洽 |
| 消费方（agent/目标仓库） | 按 references 执行工作流、校订 auto-scan 内容、维护产物文档 |

## 契约 1：skill 调用接口

`SKILL.md` 按 `$ARGUMENTS` 分派：`init [--no-generate]`（默认 init 完成后自动接续 generate 工作流；`--no-generate` 只搭骨架）/ `generate [--incremental|--scope <area>|--dry-run] [--lang zh|en]` / `sync` / `record [note|plan|handoff|lesson]`。新增子命令必须同步 SKILL.md 路由表与对应 reference 篇。

## 契约 2：脚本 CLI

| 脚本 | 关键参数 | 退出码 |
|---|---|---|
| `install.py` | `--tool --scope --link --dry-run [--force]` | 0 成功；2 参数/目标错误 |
| `init_project.py` | `[--project-name] [--lang] [--dry-run] [--overwrite] [--no-scan]` | 0 成功；2 参数错误/嵌套 git 拒绝 |
| `scan_repo.py` | `[--json]` | 0 成功；2 参数错误 |
| `check_sync.py` | `<repo-path>` | 0 全过；1 有 ❌；2 缺 AGENTS.md/aiDoc |

变更参数或退出码必须同步本表与 references 中引用处。

## 契约 3：产物结构

- 占位符：`{{PROJECT_NAME}}`、`{{DATE}}`、`<skill-dir>`、`<harness>`（init 渲染时替换，模板内禁止新增未登记的占位符）。`<skill-dir>` 渲染为 skill 安装目录；`<harness>` 仅在脚本布局符合仓库 checkout 结构时渲染为工具包仓库根，否则保留占位由用户替换。
- 标记：`<!-- auto-scan: init 扫描生成，generate 工作流校订后移除此标记 -->`（逐字，references 与脚本保持一致）；`<!-- auto-generated by scan_repo.py; do not hand-edit -->`（code-index.md，逐字）。
- aiDoc 区域全集：`relations/ modules/ contracts/ frontend/ examples/ memory/ notes/ plans/`；唯一条件性区域是 `frontend/`（has_frontend 时生成）。
- 每个 aiDoc .md（TEMPLATE 豁免）前 5 行含 `<!-- last-updated: YYYY-MM-DD -->`。

## 变更规则

- 三类契约任一变更 = 共享契约变更：先更新本文件，再改实现，references/模板/脚本检查逻辑同一次变更内完成。
- 验证：/tmp fixture 端到端（init → check_sync 全过）+ frontmatter 校验。

## 完成前检查清单

- [ ] references 中引用的参数/标记/路径与脚本逐字一致
- [ ] zh/en 模板占位符与结构镜像
