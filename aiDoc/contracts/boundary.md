# 契约层（boundary）

> 本仓库非 Web/库/传统 CLI，契约双方：生产方 = 本工具包；消费方 = 安装 skill 的 agent 与被初始化的目标仓库。

## 责任边界

| 侧 | 职责 |
|---|---|
| 生产方（本仓库） | skill 路由与 references 的正确性、脚本的安全模型与探测准确性、模板骨架的自洽 |
| 消费方（agent/目标仓库） | 按 references 执行工作流、校订 auto-scan 内容、维护产物文档 |

## 契约 1：skill 调用接口

`SKILL.md` 按 `$ARGUMENTS` 分派：`init [--no-generate]`（默认 init 完成后自动接续 generate 工作流；`--no-generate` 只搭骨架）/ `generate [--incremental|--scope <area>|--dry-run] [--lang zh|en]` / `sync` / `record [note|plan|handoff|lesson]` / `update`（工具包升级后刷新目标仓库的托管文件）。新增子命令必须同步 SKILL.md 路由表与对应 reference 篇。

## 契约 2：脚本 CLI

| 脚本 | 关键参数 | 退出码 |
|---|---|---|
| `install.py` | `--tool --scope --link --dry-run [--force] [--check]`；版本=`harness_common.git_version`（git describe），已装版本一致则 SKIP，`--check` 只报告 | 0 成功（--check 全部最新）；1 有目标被拒/失败（--check 有旧版或未安装）；2 参数/目标错误 |
| `init_project.py` | `[--project-name] [--lang auto\|zh\|en] [--dry-run] [--overwrite] [--no-scan]`（auto=探测仓库既有文档语言：中文字符占比>30% 判 zh，否则 en，回退 zh）；收尾写 `aiDoc/.harness-manifest.json` | 0 成功；2 参数错误/嵌套 git 拒绝 |
| `update_harness.py` | `[--dry-run] [--force] [--lang auto\|zh\|en]`；按 manifest 基线刷新未改文件，项目已改文件跳过；模板新增文件（模板有、manifest 无）按 下发/补登记/报告冲突 三分类处理 | 0 成功；2 参数错误/前置不满足（嵌套 git、缺 AGENTS.md/aiDoc） |
| `scan_repo.py` | `[--json] [--write-code-index [--lang auto\|zh\|en]]`（`--write-code-index` 写入唯一机器产物 `aiDoc/relations/code-index.md`，是 code-index 漂移修复路径） | 0 成功；2 参数错误 |
| `check_sync.py` | `[repo-path]`（默认 `.`；路径真实性检查白名单 = 常见源码目录 + `skills`、`templates`、`references`、`aiDoc`） | 0 全过；1 有 ❌；2 缺 AGENTS.md/aiDoc |

脚本层内部模块契约：`harness_common.py`（`find_git_root`/`read_text_relaxed`/`git_version` 唯一实现，各脚本禁止再复制）；`render_data.py`（双语展示文案表 `CONFIG_PURPOSE`/`DIR_CONVENTIONS` 唯一维护点）。

变更参数或退出码必须同步本表与 references 中引用处。

## 契约 3：产物结构

- 占位符：`{{PROJECT_NAME}}`、`{{DATE}}`、`<skill-dir>`、`<harness>`（init 渲染时替换，模板内禁止新增未登记的占位符）。`<skill-dir>` 渲染为 skill 安装目录；`<harness>` 仅在脚本布局符合仓库 checkout 结构时渲染为工具包仓库根，否则保留占位由用户替换。
- 标记：`<!-- auto-scan: init 扫描生成，generate 工作流校订后移除此标记 -->`（逐字，references 与脚本保持一致）；`<!-- auto-generated by scan_repo.py; do not hand-edit -->`（code-index.md，逐字）；`<!-- scan-fill:<key> -->`（模板内扫描填充定位点，紧邻小节标题行，zh/en 镜像各 7 处；generate 校订时连同 auto-scan 标记移除；新增填充小节须同步 `init_project.py` 的 `_fill_specs` 与 selftest 镜像检查）。
- aiDoc 区域全集：`relations/ modules/ contracts/ frontend/ examples/ memory/ notes/ plans/`；唯一条件性区域是 `frontend/`（has_frontend 时生成）。
- 每个 aiDoc .md（TEMPLATE 豁免）前 5 行含 `<!-- last-updated: YYYY-MM-DD -->`。
- `aiDoc/.harness-manifest.json`：机器产物（不手改），init 收尾写入、update 读取并更新；字段 `harness_version`/`project_name`/`lang`/`generated`/`files{rel: {sha256, template}}`，是 update_harness.py 判定"项目是否改过"的基线。

## 变更规则

- 三类契约任一变更 = 共享契约变更：先更新本文件，再改实现，references/模板/脚本检查逻辑同一次变更内完成。
- 验证：/tmp fixture 端到端（init → check_sync 全过）+ frontmatter 校验。

## 完成前检查清单

- [ ] 本文件三类契约表与实际行为一致
- [ ] references 中引用的参数/标记/路径与脚本逐字一致

（zh/en 镜像与占位符一致性属根 `AGENTS.md` Definition of Done，此处不重复。）
